# ISOBMFF scope and validation

Branch `isobmff`. Family `cutlass-isobmff`. Direction: demux and mux. This record is the capability matrix and the validation report for that crate. It does not authorize publishing, merging, or releasing.

## Request

Unqualified ISO base media file format. File types: MP4, QuickTime (`mov`), `m4a`, `m4v`, `3gp`, and fragmented MP4. HEIC is this box layout plus an HEVC item. AVIF is this box layout plus an AV1 item. JPEG, PNG, WebP, and GIF stay in `cutlass-still`. ImageIO is not used by this crate.

Rules and skills used: `.cursor/rules/container-shipping.mdc`, `codec-shipping.mdc` (boundary only; no bitstream codec was implemented), `commit-often.mdc`, `perf.mdc`, `source-of-truth.mdc`, `no-capcut-names.mdc`, `local-media.mdc`, `rust-standards.mdc`, `platforms.mdc`, `tests.mdc`, and `.cursor/skills/ship-container/` (`SKILL.md`, `references/implementation.md`, `references/verification.md`, `references/deliverables.md`, `references/movie.md`).

`cutlass-docs/rust-workspace.md` assigns this family to `crates/containers/isobmff`, depending only on `cutlass-container`. `engine` and `export` depend on the container traits and are empty files. The desktop binary already depends on this crate and its `main` only prints `cutlass`. No reader or export path was filled in.

## Specification and sources

Baseline: ISO/IEC 14496-12:2022 (edition 7), plus the usual MP4, AVC/HEVC sample-entry, QuickTime, and HEIF layouts those brands need. Edition 8 (2026) was not available as a free text, so it was not applied. These edition-8 features are unsupported: essential sample groups, essential-descriptions, preselection entity groups, EDRAP, sample-packed restricted video, the associated-external-stream track reference, an optional `HandlerBox` in `MetaBox`, a handler property for items, T.35, and original sample duration. Ordinary sample bytes do not need them.

Local files read before the implementation, and not linked into the build: FFmpeg `mov.c` and `movenc.c`, GStreamer `qtdemux.c` and `qtmux.c`, GPAC `isom_read.c` and `isom.h`, Bento4 `Ap4Atom.cpp`, `Ap4SampleTable.cpp`, and `Ap4TrunAtom.cpp`. A disagreement with the 2022 specification was resolved toward the specification. Examples: a missing `stss` means every sample is a sync sample; an empty `stss` means there is no sync sample; edit lists are not applied to packet timestamps; FFmpeg's decode-time shift is not applied.

Oracles on this machine: `ffmpeg` and `ffprobe` 8.1.1, GStreamer 1.28.3 (`gst-discoverer-1.0`, `gst-inspect-1.0`). `mp4box`, `mp4dump`, and `gpac` are not installed. Those absences are "not available", not a pass.

## Assumptions and limits

Timestamps stay in the track timescale. One packet is one sample. `pts = dts + composition offset`. Edit lists are returned as `Edit` values and are not applied.

Resource limits live in `limits.rs`: depth 32, metadata box 64 MiB, 64 tracks, 4_000_000 samples, 64 MiB packet, 4_096 edits, 32 brands, 16 sample entries, 4_000_000 table rows, 2_000_000 boxes, probe 64 bytes, 256 MiB buffered when `moov` is written first, 16 samples per fragment unless the caller sets another count.

Mux decode times on a track start at 0 and then equal the previous decode time plus that sample's duration. Presentation time may differ. The muxer always writes `co64` (one sample per chunk). It does not write `sidx`. Fragmented output writes `mfra` with `tfra` version 1 and length-size bytes of zero. `mvhd`, `tkhd`, `mdhd`, and `elst` are version 0; a duration that does not fit in `u32` is stored as `u32::MAX`. A single box whose payload does not fit in `u32` is not produced. Only the first sample description's extradata is exposed. A HEIF grid is one packet per item, not a reconstructed image. An external `dref` (`url` or `urn` with the self-contained flag clear) is `ExternalReference` at open. `probe` can return true when `ftyp` is larger than the 64-byte buffer; `open` is authoritative.

## Validation report

### 1. Implementation

Demux and mux are both in this crate. Modules: `brand`, `demux`, `fragment`, `heif`, `index`, `limits`, `movie`, `mux`, `parse`, `stsd`. Public entry points: `probe`, `IsoBmff::open`, `IsoBmffMux`, `MuxOptions`, `FileBrand`. The crate implements `Demux` and `Mux`. Packet times are file ticks. Codec payloads are not decoded.

`cutlass-codec` gained the shared id, packet, and parameter types. `cutlass-container` gained `Demux`, `Mux`, `Source`, `Error`, and `Edit`, and re-exports the codec types so this crate does not depend on `cutlass-codec` directly. `engine` and `export` were not given a reader or an exporter.

### 2. Rules

The instruction paths are the list in the request section. `cargo lint` is `clippy --workspace --all-targets -- -D warnings`. `unsafe_code` is forbidden. Library code does not unwrap, expect, or panic. No `cc`, `cmake`, `bindgen`, `nasm-rs`, or ffmpeg crate was added. `deny.toml` licenses and bans stayed as they were.

The workspace document says ImageIO is tried first for HEIC and AVIF on Apple. That path is a platform concern. This crate is the Rust parser and does not call ImageIO.

### 3. Capabilities

The matrix above is the result. Still unsupported, and not treated as done: edition 8 features, HEIF grid reconstruction, AVIF without a fixture, mux `sidx`, mux `stco`, version-1 movie headers for durations above `u32::MAX`, more than one sample description's extradata, and an external media file. A failed fragment write that has already emitted `moof` does not roll back that `moof`.

### 4. Correctness

Independent producers: ffmpeg 8.1.1 for progressive MP4, fragmented MP4, and QuickTime. Independent check of the progressive file: ffprobe and GStreamer 1.28.3. GPAC and Bento4 tools were not available.

`ffmpeg_and_gstreamer_see_the_same_packets` passed. For each file, packet count, payload sha256, size, duration, keyframe, and composition offset (`pts - dts`) matched ffmpeg `-c copy -f framehash -hash sha256`. Absolute dts and pts differed by one constant per file. That constant is ffmpeg's decode-time shift. This crate does not apply it. The test requires the shift to be the same for every packet in the file.

Self round trips cover `moov` at either end, brands, edits, interleave, fragments, and an unknown fourcc. They are supplementary to the ffmpeg comparison.

### 5. Timing and seek

Durations accumulate in the track timescale (`durations_accumulate_in_the_file_timescale`). Edits are not applied. Seek lands on the sync sample at or before the time, including before the first sample, between keyframes (preroll 1 when the second sample is not sync), and past the end. Fragment seek with `samples_per_fragment: 1` lands on the earlier sync sample and the following read is that sample, then the delta. The landed sample is read; the media prefix before it is not (`seek_reads_the_landed_sample_and_not_the_media_prefix`).

### 6. Lifecycle and integration

Empty input is `Truncated`. RIFF is `NotThisFamily` before a huge size is treated as hostile. A muxer dropped before `finish` leaves an unpatched largesize and no `moov`; open returns `HostileSize { at: 28, claimed: 0 }`. A payload write that fails once can be retried at the same decode time. Timescale 0, a packet timescale that does not match the track, and a decode time that does not continue the track are rejected.

There is no cancellation token. The desktop binary does not open a file. `engine` and `export` do not call this crate. That integration is a scaffold, not a pass.

### 7. Robustness

Malformed cases in the matrix return typed errors. The demux fuzz target is `probe`, `open`, `read_packet` (up to four packets), and `seek`. Every fifth iteration mutates a valid 4-sample movie; the others mutate a random buffer. The mux fuzz writes one to three tracks and up to twelve bounded packets, rejects a decode time that skips 0, finishes, and compares the reopened packets.

Demux campaign: `ISOBMFF_FUZZ_SECS=1800`, seed `0x150bf00d`, debug profile. Result: 3,082,048,620 iterations, exit 0, no panic. Most inputs fail the family check immediately; every fifth input is a mutated 4-sample movie that is opened, read, and seeked.

Mux campaign: `ISOBMFF_MUX_FUZZ_SECS=300`, seed `0x150bf11d`, debug profile, target directory `/tmp/isobmff-check`. Result: 7,415,874 iterations, exit 0, no panic and no round-trip mismatch.

No minimized regression was added from a campaign finding. The interleave bug found by an 8-second mux smoke test, before the 300-second campaign, was fixed and locked by `a_fragment_keeps_the_caller_interleave`. The clock bug found by inspection was locked by `a_failed_payload_write_keeps_the_decode_time`.

### 9. Performance

Hardware: Apple M5 Pro, 18 cores, 48 GiB. Release profile. File: 4000 samples, 16 bytes each, one video track, `moov` after `mdat`, 97160 bytes. Index is at the end. Open reads the sample tables; seek uses that index.

Latest release run of `open_and_seek_stay_under_a_coarse_bound`: open 84.209µs, seek 250ns. Budget: open under 2s, seek under 500ms. Passed. This is one sample, not a statistical benchmark. Allocation counts and peak memory were not instrumented. The seek test that counts reads shows the header scan stays at or under 16 bytes and the read after the seek is the landed 64-byte sample.

Debug, before the mux ordering fixes: open 806.416µs, seek 2µs, same file size. An earlier release sample on that older binary was open 61.458µs, seek 14.917µs. The later release sample is the one that matches this tree.

### 10. Conclusion

**Partial.** Demux and mux for the ordinary movie, QuickTime, M4A, M4V, 3GP, and fragmented (`mfra`) files above are implemented and the executed checks passed, including ffmpeg packet bytes and this machine's local files. The result is partial because:

- `engine` and `export` do not open or write a file. The desktop binary does not either.
- End-to-end seek of a file whose only fragment index is `sidx` has no fixture. The `sidx` parser itself is tested.
- AVIF items, HEIF grids, edition 8 boxes, and mux `sidx` are unsupported or untested, as the matrix says.
- GPAC and Bento4 were not available as a second and third independent demuxer. GStreamer confirmed the progressive file's codec and width; it was not a packet-hash oracle.
- Allocation and peak-memory figures were not measured.

Reproduce the report with:

```sh
cargo fmt --all -- --check
cargo lint
cargo test --workspace
cargo deny check
cargo test -p cutlass-isobmff --release --lib open_and_seek_stay_under_a_coarse_bound -- --nocapture
ISOBMFF_FUZZ_SECS=1800 cargo test -p cutlass-isobmff --lib fuzz_probe_open_read_seek_for_the_requested_budget -- --nocapture
ISOBMFF_MUX_FUZZ_SECS=300 cargo test -p cutlass-isobmff --lib fuzz_mux_bounded_packets_for_the_requested_budget -- --nocapture
```

The timed fuzz tests print `not run` and succeed when those variables are unset, so a normal `cargo test` does not repeat the campaigns.
