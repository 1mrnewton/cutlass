libaom oracle build, when run locally:

```
cmake -DCMAKE_BUILD_TYPE=Release -DCONFIG_AV1_ENCODER=1 -DCONFIG_AV1_DECODER=1 \
  -DENABLE_TESTS=0 -DENABLE_DOCS=0 -DENABLE_EXAMPLES=1 -DCONFIG_MULTITHREAD=0 \
  -DCONFIG_LIBYUV=0 -DCONFIG_WEBM_IO=0 -DAOM_TARGET_CPU=generic
cmake --build . --target aomdec aomenc
```

`AOM_TARGET_CPU=generic` is the scalar oracle configuration used when `nasm`
is not installed. That configuration was built from the pin above. One
16×16 lossless constant frame matched `aomdec` (see `COVERAGE.md`). That
match is not a profile conformance run.

`aomdec` comparisons disable film grain with `--skip-film-grain` for the
reconstruction mode and leave grain on for the presentation mode. No
`--output-bit-depth` downshift. Raw planar output (`--rawvideo` / y4m) is
compared sample-wise.

Coefficient CDFs and quantizer lookups are generated by
`crates/cutlass-codec-av1/tools/extract_coeff_tables.py` from the pinned
libaom tree. libaom stores inverse CDFs (`AOM_ICDF`); the script emits the
specification's forward CDF plus the adaptation counter. Mode CDFs in
`src/cdf.rs` were transcribed from `av1/common/entropymode.c` at the same pin.
Those tables are BSD-2-Clause data from the Alliance for Open Media. The
notice is in `crates/cutlass-codec-av1/NOTICE`.

Quantizer lookup tables are the specification's `Dc_Qlookup` / `Ac_Qlookup`
(section 7.12.2 in the errata-1 numbering; the markdown section is
"Dequantization functions"). They match libaom `dc_qlookup_*_QTX` /
`ac_qlookup_*_QTX` at this pin.

No production path links libaom, dav1d, libgav1, or FFmpeg.
